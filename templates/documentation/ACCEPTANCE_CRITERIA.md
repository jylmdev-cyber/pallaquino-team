# Plantilla: Criterios de aceptación

Propósito y ejemplo aplicado al kit: [documento de referencia](../../docs/business/ACCEPTANCE_CRITERIA.md).

Al adaptarlo: describir únicamente hechos confirmados de su proyecto, vincular requisitos y tareas, indicar responsable y fecha, y aportar evidencia reproducible. Si falta una decisión, declarar la pregunta y quién la resolverá. No copiar las capacidades de UASEK como si pertenecieran a su aplicación.

Guía de contenido para este documento: AC-01: init en carpeta existente devuelve 2 y conserva contenido. AC-02: task done sin evidencia falla. AC-03: audit sin autorización no invoca Git. AC-04: handoff omite .env y redacta patrones conocidos. AC-05: fallos de OSV no producen estado limpio. AC-06: docs conserva archivos humanos. AC-07: tests vacíos no habilitan release. AC-08: cambio de código invalida el reporte de test para release. Evidencia ejecutable en tests/test_core.py.
