# Plantilla: Historias de usuario

Propósito y ejemplo aplicado al kit: [documento de referencia](../../docs/business/USER_STORIES.md).

Al adaptarlo: describir únicamente hechos confirmados de su proyecto, vincular requisitos y tareas, indicar responsable y fecha, y aportar evidencia reproducible. Si falta una decisión, declarar la pregunta y quién la resolverá. No copiar las capacidades de UASEK como si pertenecieran a su aplicación.

Guía de contenido para este documento: US-01 Como coordinador quiero identificar tareas listas para encargar trabajo sin saltar dependencias. US-02 Como desarrollador quiero cambiar de asistente conservando decisiones y pendientes. US-03 Como propietario quiero autorizar auditoría y revisar resultados antes de modificar. US-04 Como revisor quiero códigos distintos para vulnerabilidad, error y cobertura desconocida.
