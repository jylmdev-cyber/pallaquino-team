# Domain Driven Design

## Entradas y parámetros

Procesos y vocabulario. Usar la ruta del proyecto, alcance y criterios del encargo. Marcar datos faltantes como pendientes; no inventarlos.

## Procedimiento

Acordar glosario, invariantes y fronteras de consistencia con negocio. Usar contextos cuando el mismo término tenga significados distintos.

## Ejemplo

Cliente de facturación y destinatario logístico tienen ciclos distintos.

## Dependencias

Contrato del agente asignado y PROJECT MEMORY. Para comandos del kit: Python 3.11+ y checkout de UASEK; los comandos de red o Git requieren esas capacidades cuando se indiquen.

## Finalización verificable

Invariantes y propietarios de datos definidos. Registrar archivos y resultado de comprobaciones, incluidos los fallos o pruebas no ejecutadas.
