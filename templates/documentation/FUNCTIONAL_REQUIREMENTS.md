# Plantilla: Requisitos funcionales

Propósito y ejemplo aplicado al kit: [documento de referencia](../../docs/business/FUNCTIONAL_REQUIREMENTS.md).

Al adaptarlo: describir únicamente hechos confirmados de su proyecto, vincular requisitos y tareas, indicar responsable y fecha, y aportar evidencia reproducible. Si falta una decisión, declarar la pregunta y quién la resolverá. No copiar las capacidades de UASEK como si pertenecieran a su aplicación.

Guía de contenido para este documento: RF-01 init crea destino nuevo. RF-02 task administra dependencias y exige evidencia al cerrar. RF-03 context/handoff exporta diez secciones redactadas. RF-04 provider declara capacidades y bloquea API cloud ausente. RF-05 audit exige autorización. RF-06 test rechaza cero pruebas. RF-07 backup no sobrescribe y crea manifiesto. RF-08 agent validate revisa referencias sin ejecutar comandos declarados.
